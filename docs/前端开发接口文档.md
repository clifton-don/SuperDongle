# SuperDongle 前端开发接口文档

> 本文档面向 **前端开发人员**，说明 SuperDongle 设备 Web 管理面板的 HTTP REST API 及 WebSocket 接口规范。  
> 嵌入式固件已实现全部后端逻辑（ESP-IDF 5.5.4），前端只需按此文档调用 API 即可完成交互。

## 1. 设备连接与访问

### 1.1 连接方式

| 方式 | 说明 | 访问地址 |
|------|------|----------|
| **AP 直连** | 设备上电后发出热点 `SuperDongle`，密码 `12345678` | `http://192.168.5.1` |
| **局域网连接** | 设备连接路由器后，通过 mDNS 或 IP 访问 | `http://superdongle.local` 或 DHCP 分配 IP |
| **USB 连接** | 通过 USB 线连接电脑，设备会枚举为 U 盘（MSC 设备） | 文件管理中可直接操作 SD 卡 |

### 1.2 mDNS 服务

设备注册 mDNS 服务 `_http._tcp`，主机名默认为 `superdongle`，可通过设置页面修改。

## 2. 通用约定

### 2.1 基础 URL

```
http://<device-ip>/
```

### 2.2 响应格式

所有 API 返回 JSON。成功示例：

```json
{ "ok": true }
```

错误示例：

```json
{ "ok": false, "error": "busy" }
```

### 2.3 路径遍历防护

所有涉及文件路径的接口均已内置 `../` 路径遍历防护，非法路径返回 `400 Bad Request`。

### 2.4 URL 编码

查询字符串中的 `ssid`、`password`、`filename` 等参数需进行 URL 编码（`encodeURIComponent`）。

## 3. WiFi 配网 API

### 3.1 获取 WiFi 状态

```
GET /api/wifi/status
```

**响应示例：**

```json
{
  "connected": true,
  "state": 2,
  "ssid": "MyHomeWiFi",
  "ip": "192.168.1.100",
  "rssi": -45,
  "mode": "AP+STA",
  "hostname": "superdongle"
}
```

**state 取值：**

| 值 | 含义 |
|----|------|
| 0 | 空闲/未连接（IDLE） |
| 1 | 正在连接（CONNECTING） |
| 2 | 已连接（CONNECTED） |
| 3 | 连接失败（FAILED） |

---

### 3.2 扫描附近 WiFi

```
GET /api/wifi/scan
```

**响应示例：**

```json
{
  "items": [
    { "index": 0, "ssid": "HomeWiFi", "rssi": -45, "auth": 3 },
    { "index": 1, "ssid": "NeighborWiFi", "rssi": -67, "auth": 2 }
  ]
}
```

**auth 认证模式取值：**

| 值 | 含义 |
|----|------|
| 0 | 开放（Open） |
| 1 | WEP |
| 2 | WPA_PSK |
| 3 | WPA2_PSK |
| 4 | WPA_WPA2_PSK |
| 5 | WPA2_ENTERPRISE |
| 6 | WPA3_PSK |
| 7 | WPA2_WPA3_PSK |

---

### 3.3 获取已保存 WiFi 列表

```
GET /api/wifi/saved
```

**响应示例：**

```json
{
  "items": [
    { "index": 0, "ssid": "HomeWiFi" },
    { "index": 1, "ssid": "OfficeWiFi" }
  ]
}
```

---

### 3.4 连接 WiFi（表单方式）

```
POST /api/wifi/connect?ssid=<SSID>&password=<PASSWORD>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| ssid | 是 | WiFi 名称（URL 编码） |
| password | 否 | 密码，不传或空串表示开放网络 |

**响应：**

```json
{ "ok": true }
```

> ⚠️ 连接成功后设备会切到 STA 模式，AP 热点将在 20 秒后关闭。前端应提示用户切换到同一网络后重新访问。

---

### 3.5 连接已保存 WiFi

```
POST /api/wifi/saved/connect?ssid=<SSID>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| ssid | 是 | 已保存的 WiFi 名称 |

---

### 3.6 删除已保存 WiFi

```
POST /api/wifi/saved/delete?ssid=<SSID>
```

## 4. 文件管理 API（SD 卡）

SD 卡挂载路径为 `/disk`，所有文件操作均在此路径下。

### 4.1 获取文件列表

```
GET /api/msc/filelist?dir=<子目录>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| dir | 否 | 子目录路径，不传则列出根目录 |

**响应（chunked 分块 JSON）：**

```json
{
  "files": [
    { "name": "photo.jpg", "type": "file", "size": 2048000, "mtime": 1700000000 },
    { "name": "Documents", "type": "directory", "size": 0, "mtime": 1700000000 }
  ]
}
```

> `mtime` 为 Unix 时间戳（秒）。

---

### 4.2 上传文件

```
POST /api/msc/upload?filename=<路径>&mtime=<时间戳>
```

| 参数 | 必填 | 说明 |
|------|------|------|
| filename | 是 | 文件路径（相对于 SD 卡根目录），如 `docs/report.pdf` |
| mtime | 否 | 文件时间戳（Unix 秒），留空则为当前时间 |

**请求体：** 二进制文件内容（`Content-Type` 无需设置）。

**特点：** 后端使用 **32KB 乒乓 DMA 缓冲 + 异步写入流水线**，上传大文件时不会阻塞 HTTP 线程。文件已存在时返回错误。

---

### 4.3 下载文件

```
GET /api/msc/download?filename=<路径>
```

**响应：** 二进制文件流，附带 `Content-Disposition: attachment` 和 `Content-Length`。

---

### 4.4 预览文件（支持 Range）

```
GET /api/msc/preview?filename=<路径>
```

**特点：**
- 支持 HTTP `Range` 请求头，用于视频/音频渐进式播放
- Range 最大响应 2MB
- 返回正确的 `Content-Type`（根据扩展名自动识别）

**支持预览的格式：** html, css, js, png, jpg, gif, ico, svg, mp4, webm, mp3, wav, flac, ogg, pdf 等。

---

### 4.5 批量删除

```
POST /api/msc/batch-delete
Content-Type: application/json

{
  "files": ["file1.txt", "dir1", "photo.jpg"],
  "dir": "subfolder"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| files | 是 | 要删除的文件/目录名称数组 |
| dir | 否 | 父目录路径，空串表示根目录 |

> 支持递归删除目录及其内容。

---

### 4.6 新建文件夹

```
POST /api/msc/mkdir
Content-Type: application/json

{
  "dir": "parent",
  "name": "newfolder",
  "mtime": 1700000000
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| dir | 否 | 父目录路径，空串或不传表示根目录 |
| name | 是 | 新文件夹名称 |
| mtime | 否 | 时间戳 |

---

### 4.7 重命名

```
POST /api/msc/rename
Content-Type: application/json

{
  "dir": "parent",
  "oldName": "old.txt",
  "newName": "new.txt",
  "mtime": 1700000000
}
```

---

### 4.8 移动文件

```
POST /api/msc/move
Content-Type: application/json

{
  "files": ["file1.txt", "file2.txt"],
  "sourceDir": "src",
  "targetDir": "dst"
}
```

> 仅支持同个 SD 卡内的移动操作。

---

### 4.9 获取存储状态

```
GET /api/msc/status
```

**响应示例：**

```json
{
  "mounted": true,
  "total_mb": 31000,
  "free_mb": 15000
}
```

---

### 4.10 软重启 USB MSC

```
POST /api/msc/restart
```

重新枚举 USB MSC 设备，用于上位机重新识别。

## 5. 设备设置 API

### 5.1 获取 LED 状态

```
GET /api/settings/led/state
```

**响应：**

```json
{ "enabled": true }
```

---

### 5.2 保存 LED 设置

```
POST /api/settings/led/save
Content-Type: application/json

{ "enabled": false }
```

---

### 5.3 保存 mDNS 主机名

```
POST /api/settings/mdns/save
Content-Type: application/json

{ "hostname": "mybox" }
```

**校验规则：**
- 长度 1~31 字符
- 仅允许字母（a-z, A-Z）、数字（0-9）和连字符（-）
- 不能以连字符开头
- 保存后写入 NVS，**重启设备后生效**

**响应：**

```json
{ "ok": true }
```

## 6. OTA 升级 API

### 6.1 获取 OTA 状态

```
GET /api/ota/status
```

**响应示例：**

```json
{
  "current_version": "1.0.0",
  "update_available": true,
  "new_version": "1.1.0",
  "description": "Bug fixes and performance improvements",
  "busy": false,
  "progress": 0,
  "has_firmware": true,
  "has_spiffs": true,
  "error": false,
  "status_msg": ""
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| current_version | string | 当前固件版本 |
| update_available | bool | 是否有可用更新 |
| new_version | string | 远程最新版本号 |
| description | string | 更新说明文本 |
| busy | bool | 是否正在更新中 |
| progress | int | 下载进度 0~100 |
| has_firmware | bool | 本次更新是否包含固件 |
| has_spiffs | bool | 本次更新是否包含网页文件 |
| error | bool | 上次更新是否出错 |
| status_msg | string | 当前状态描述 |

---

### 6.2 检查更新

```
POST /api/ota/check
```

从远程 `version.json` 获取版本信息并比较。

**响应：**

```json
{ "ok": true, "update_available": true }
```

**version.json 格式（部署在 OTA 服务器上）：**

```json
{
  "version": "1.1.0",
  "url": "https://example.com/firmware/v1.1.0.bin",
  "spiffs_url": "https://example.com/firmware/v1.1.0.spiffs.bin",
  "description": "Bug fixes and performance improvements",
  "firmware_enabled": true,
  "spiffs_enabled": true,
  "force": false
}
```

| 字段 | 说明 |
|------|------|
| version | 版本号（与本地 CONFIG_APP_PROJECT_VER 比较） |
| url | 固件 bin 下载地址 |
| spiffs_url | SPIFFS 网页固件下载地址 |
| description | 更新说明 |
| firmware_enabled | 是否启用固件更新 |
| spiffs_enabled | 是否启用网页文件更新 |
| force | 强制更新（跳过版本比较） |

---

### 6.3 开始更新

```
POST /api/ota/update
```

**响应：**

```json
{ "ok": true, "status": "updating" }
```

**更新流程：**

1. 如果有固件更新 → 下载固件到 OTA 分区 → 设置启动分区
2. 如果有 SPIFFS 更新 → 下载到非活跃分区 → 切换活跃标志
3. 全部完成后 → 自动重启

---

### 6.4 取消更新

```
POST /api/ota/cancel
```

## 7. 前端页面说明

### 7.1 页面路由

| 页面 | 文件 | URL |
|------|------|-----|
| WiFi 配网 | `index.html` | `/` 或 `/index.html` |
| 文件管理 | `files.html` | `/files.html` |
| HID 键鼠控制 | `hid_devices.html` | `/hid_devices.html` |
| 静态资源 | `app.js` / `app.css` | 自动由 404 fallback 路由 |

> 所有静态文件存储在 SPIFFS 分区中，通过 404 fallback handler 自动路由。

### 7.2 页面集成

底部导航栏按钮切换页面通过 `iframe` 嵌入子页面：

```html
<iframe src="/files.html"></iframe>
<iframe src="/hid_devices.html"></iframe>
```

各子页面为独立 SPA，通过 `BroadcastChannel`（`superdongle_lang` / `superdongle_theme`）与主页面同步语言和主题设置。

### 7.3 多语言支持

前端使用 `data-i18n` 属性实现中英文切换，支持的语言包在 `app.js` 的 `i18n` 对象中配置。

### 7.4 主题切换

支持深色/浅色两种主题，通过 `data-theme` 属性切换，主题变量定义在 `app.css` 的 CSS 自定义属性中。

## 8. HID 键鼠控制 API

> SuperDongle 通过 USB HID 转发键鼠操作到被控设备。前端通过一个 WebSocket 二进制帧接口完成键盘、鼠标、剪切板粘贴全部功能。

### 8.1 检测 HID 模式

```
GET /api/usb/status
```

```json
{ "mode": 1 }
```

| mode | 含义 |
|------|------|
| 0 | MSC（U 盘模式） |
| 1 | HID（键鼠转发模式） |

---

### 8.2 WebSocket 端点

```
ws://<device-ip>/api/hid/ws
```

- 仅接受**二进制帧**（`ws.binaryType = 'arraybuffer'`）
- 同时只允许 1 个连接，新连接自动踢旧连接

---

### 8.3 二进制帧协议

第 1 字节为帧类型，决定后续字节含义。

#### 8.3.1 鼠标帧 — `0x01`（5 字节）

| 偏移 | 长度 | 类型 | 含义 |
|------|------|------|------|
| 0 | 1 | uint8 | 帧类型 `0x01` |
| 1 | 1 | int8 | 水平位移 dx（正值右移，-127~127） |
| 2 | 1 | int8 | 垂直位移 dy（正值下移，-127~127） |
| 3 | 1 | uint8 | 按钮位掩码 |
| 4 | 1 | int8 | 滚轮 wheel（正=上滚，负=下滚） |

按钮位掩码：

| 位 | 值 | 按钮 |
|----|----|------|
| bit 0 | 1 | 左键 |
| bit 1 | 2 | 右键 |
| bit 2 | 4 | 中键 |
| bit 3 | 8 | 后退 |
| bit 4 | 16 | 前进 |

#### 8.3.2 键盘帧 — `0x04`（3 字节）

| 偏移 | 长度 | 类型 | 含义 |
|------|------|------|------|
| 0 | 1 | uint8 | 帧类型 `0x04` |
| 1 | 1 | uint8 | 按下=1，释放=0 |
| 2 | 1 | uint8 | HID 键码（见 [8.4 键码表](#84-hid-键码参考)） |

修饰键（Ctrl/Shift/Alt/GUI，键码 0xE0-0xE7）固件自动放入 HID modifier byte，前端无需特殊处理。普通键最多 6 键同时按下。

#### 8.3.3 粘贴帧 — `0x05`（3 + N×2 字节）

| 偏移 | 长度 | 类型 | 含义 |
|------|------|------|------|
| 0 | 1 | uint8 | 帧类型 `0x05` |
| 1 | 1 | uint8 | 按键数量 高字节 |
| 2 | 1 | uint8 | 按键数量 低字节 |
| 3+ | N×2 | uint8[] | [code, shift] 对数组 |

每对 2 字节：code 为 HID 键码，shift 为 1 时固件自动按下左 Shift。最多 512 对（1024 字节 payload）。固件收到后逐键播放（打字机方式），不在映射表中的字符自动跳过。
